# 奶娃助手：桌宠与 AI 电脑助手功能调研及选择清单

调研日期：2026-10-10。以本次修复后的代码为现状，参考产品官方页面、开发者文档及公开源码。没有安装并长期试用这些竞品，也没有进行同机性能对比；官方宣称、代码现状和我的产品建议分别注明。以下新增功能尚未实施，交由你选择。

我的建议是优先把奶娃做成“常驻桌面、随手唤起、任务过程清楚、失败能恢复”的个人助手。保留 pi 内核，把设置复杂度藏在需要的时候；不增加插件商店、团队代理或另一套内核。

## 1. 参考了什么，值得学什么

| 参考产品 | 官方资料中可确认的能力 | 对奶娃有价值的借鉴 | 不必照搬的部分 |

## 4. 重要功能怎样才算做完

### F01：恢复任务，不重复已执行的动作

例子：“整理这批文件”做到一半断网。打开助手应看到已完成 3 步、失败步骤、错误原因和继续按钮；不能只能重新发送原问题。最低实现是任务 ID、目标、已执行调用摘要、会话 ID、失败点和状态持久化。

验收：网络中断、关闭窗口、应用退出/重启、人工取消分别测试；恢复后先重新核对外部状态。已发送消息、已运行命令等不得盲目重复。Pi 会话恢复只恢复对话上下文，不能自动证明外部操作可无条件续跑。最新官方 RPC 文档也明确“收到 prompt 成功”与“任务结束”不同；实现前还需按随包版本确认事件和命令。来源：[Pi RPC 生命周期](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/rpc.md)。

### F02：看到真实结果，并诚实区分可撤回操作

第一版只做文本文件：操作前保存原内容，完成后展示 diff，用户选恢复。PDF/图片先提供预览和打开位置；不承诺所有格式都能编辑/回滚。鼠标点击、第三方提交、系统命令等只能提供操作记录，通常不能自动撤回。

验收：文件不存在、新建文件、失败写入、用户随后修改文件、恢复时冲突，都有明确反馈；撤回不能静默覆盖用户的新修改。预览需显示实际产物，模型口头“完成”不能触发成功状态。启发来自 [DeepSeek Harness 的结果与差异展示](https://www.deepseek.com/en/harness/)，撤回边界是我的实现建议。

### F03：不挡工作，但重要提醒不莫名消失

全屏、长时间输入、手动免打扰分别设置。默认停止普通跑动/欢迎音，桌宠到边缘停靠；提醒聚合到待办，在退出全屏时一次呈现，避免连续大笑。重要闹钟是否例外应由你设置。

验收：游戏/浏览器视频/最大化普通窗口分别检查，最大化不能误当全屏；切换显示器、睡眠唤醒、热插拔后仍能找回桌宠。按你的要求，提醒与胜利保留大笑，安迪仅用于启动和打开助手。边缘收起借鉴 [Desktop Mate 开发者描述](https://store.steampowered.com/app/3301060/Desktop_Mate/)，全屏/声音策略是针对奶娃的建议。

### F04：连接失败时能自己排查

保留已有模型/档位选择，用服务商档案保存多套配置。诊断按网络→鉴权→模型对话→工具调用→图片输入分层，展示通过哪层和下一步操作。模型列表出现一个名称，不代表它支持思考、图片或工具。需要实际验证的能力应提供显式测试按钮，标清可能产生小额接口调用。

验收：错误密钥、错误地址、404 模型、429、超时、服务商不返回能力元数据、保存失败、重启/目录迁移分别测试；失败不清空原档案，日志不显示密钥。现有 `agent-service.js:testConnection` 只做一次普通文字请求，不能替代这些能力测试。

### F05/F06：看得清、停得住、费用不乱报

屏幕分享明确显示所选对象，支持只选一个窗口或区域；停止自动采集后仍需说明已发送给模型的图片不会因此收回。全局停止应先清理排队输入，再中止任务，界面说明已开始的原生动作可能执行完。

费用只有拿到可信价格/用量时才显示估算，否则显示“未知”，自定义模型的 0 成本元数据不能当成免费。阈值只是本地控制，服务商最终账单仍可能包含已发出的请求。视觉范围借鉴 [Copilot Vision 的主动共享与停止](https://support.microsoft.com/en-gb/microsoft-365-copilot/get-started-vision-microsoft-365-copilot)；其余是本产品建议。

### F07/F08：上下文准确，比无限记忆更有用

文件附件第一步限制可读文本与有文字层的 PDF，扫描 PDF/OCR 和复杂 Office 解析另选；大文件给截断提示、页数和范围。记忆保持短小，允许用户逐条编辑/禁用，敏感值不自动记忆。当前分支或工作区所用记忆应看得见。

验收：中文路径、空文件、乱码、超限附件、扫描 PDF、同名不同目录、附件被移动、任务中删除记忆。不能把文件路径当成模型已经读过文件的证据。

### F09/F10：让排队与重复任务可控

第一阶段只展示与编辑现有消息队列，不增加多 agent。第二阶段的固定流程只保存你明确选择的输入和目录，计划运行前核对授权、账户和当前桌面状态；前次未结束时不并发启动同一流程。

验收：重启后任务是否补跑、错过时间、时区/夏令时、睡眠唤醒、前次还在执行、模型额度耗尽、等待批准，均有明确策略。涉及发消息、付款、删除等动作不能因为“定时”而跳过批准。定时能力参考 [DeepSeek Harness](https://www.deepseek.com/en/harness/)，错误定位与有限重试参考 [Power Automate Desktop](https://learn.microsoft.com/en-us/power-automate/desktop-flows/errors)。

### F11/F12/F13/F14：保持个人桌宠的轻量感

F11 最小版本只加难度、最佳成绩、重新挑战，不先做完整养成体系。F12 不引入其他音效，调节你已经指定的两种素材。F13 优先让升级前后数据可核对，跨 Windows 账户导入密钥要重新填写，不能伪装成解密成功。F14 先转文字再发送，不自动开放常驻麦克风，也不加语音回复；本地识别可能增加模型文件、CPU/GPU占用，远程识别会增加服务调用与网络依赖。

触摸/拖动交互参考 [VPet](https://github.com/LorisYounger/VPet)，语音与中断参考 [Open-LLM-VTuber](https://github.com/Open-LLM-VTuber/Open-LLM-VTuber)。其他范围与优先级是我的判断。

## 5. 审美和精简的约束

这些约束适用于你决定添加的任何功能：

1. 主界面保留“输入、模型/思考、当前状态、结果”四类入口。普通使用不要求打开一页参数；高级配置收在设置。
2. 奶龙负责品牌入口、窗口/任务栏图标、等待/成功/失败动作；具体工具按钮保留能辨识动作的形状和文字。让所有功能按钮都变成相同角色图案，会增加寻找成本。
3. 保持当前奶油白/柔和深色及主题变量。状态同时用文字表达，不能只有颜色；思考过程、工具详情默认折叠，关键失败和待确认信息显式展开。
4. 提醒、小游戏成绩、任务进度有明确显示优先级，避免互相覆盖；声音与动画反馈必须和同一次状态转换相连。
5. 多屏/DPI、键盘操作、中文长文本、小窗口和高对比度要有实际验收。性能先测当前基线，再制定空闲 CPU、内存、动画帧率和唤起耗时目标；本次没有测量，不能虚构达标数字。

## 6. 暂不建议加

插件商店、团队/多代理协作、多角色同时常驻、复杂抽卡/货币养成、常驻摄像头、全时屏幕录制、自动模仿你的长期行为、大量更换皮肤素材、把任何工具失败都无限重试、后台任务默认全自动操作。这些与精简优先的目标冲突，或增加资源/维护成本而尚无明确需求。

Office/浏览器深度自动化可以以后单独选择一个高频场景，但不建议第一步宣称支持所有桌面软件。“能调用鼠标”与“能稳定完成整个工作流”需要分别验收。

## 7. 你只需要选编号

建议默认组合：**第一批 F01、F02、F03、F04；第二批 F05、F06、F07**。也可以只选择更轻的 F03、F04、F11、F12。每个功能都可以单独决定添加、暂缓或不要；本报告没有据此自动修改程序。

实际实施顺序应按你选择的编号，再细化为最小版本与验收场景。所有内容继续围绕现有 pi 内核；无需插件生态或团队代理。
